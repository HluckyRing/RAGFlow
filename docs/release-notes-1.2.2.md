# v1.2.2 — 安全两刀半 + 缺口清单更准

> 自 v1.2.1 起 8 个提交。**有一个需要你注意的默认值**：`AUTH_TOKEN` 现在**逐请求校验**
> （以前只在启动时检查），对外部署请确认客户端带 Basic 凭证；本机回环 + 空 token 行为不变。
> 回退：`COOKIE_SECURE=0`、`SESSION_BIND_LEGACY=1` 回到旧行为，或退到 v1.2.1。

## 亮点

### 1. `AUTH_TOKEN` 真的生效了（安全）

以前 `AUTH_TOKEN` **只在启动时**被检查，请求到达时一次都没校验 —— 对外部署设了 token，
实际上谁都能读写全部对话，还带着「我设过 token」的错觉。现在所有请求都要带 HTTP Basic
凭证（用户名随便填、密码 = token，时序安全比较），写操作还要求 `Origin` 与 `Host` 同源
（浏览器会自动带 Basic 凭证，必须防 CSRF）。**没设 token（默认本机回环）逐位不变。**

### 2. 会话归属：别人拿到你的 `session_id` 也进不来（安全）

`session_id` 是客户端生成的，以前服务端对任何 sid 都无条件加载状态 —— 而 sid 天天出现在
URL 里（`?session_id=…`、预览链接、浏览历史）。现在 `/api/session` 下发 **HttpOnly cookie**
（值 `sid.token`），状态里**只存 `sha256(token)`**，其余接口一律要求「cookie 的 sid 与 token
都对得上」，否则 403。刷新页面、重开浏览器都还在（cookie 有效期内）。

### 3. cookie 的 `Secure` 与旧会话迁移窗口（安全）

- `COOKIE_SECURE=auto|1|0`：`auto`（默认）按**这次请求的真实 scheme** 决定（直连看 scheme，
  反代看 `X-Forwarded-Proto` 首个值）—— 本机 http 不加（加了浏览器会丢 cookie，表现成
  「刷新就掉会话」），套了 HTTPS 自动加。
- `SESSION_BIND_LEGACY=1|0`：升级前建的旧会话没有归属令牌，默认仍允许「首次绑定」
  （不然升级后老会话当场失效）；但它对**已经泄漏过的旧 sid** 是一次抢先绑定窗口，
  把老会话清干净后建议设 `0`，之后旧 sid 会直接换新会话。

### 4. 覆盖说明的缺口清单更准了（检索透明度）

覆盖说明以前只说「本次只摘录了 12/122 段」，看不出缺什么。v1.2.1 起会点名缺的页标题；
这一版在真实语料（36 份文件 / 2886 块）上量掉三个毛病：

- **行政页不再霸榜**：频次最高的缺口条目以前是「课程思政小讲堂」「学 习 进 步 ！」「第二次作业」
  （每章 PPT 末尾那页，内容为零）—— 噪音表用子串匹配、真实文本逐字带空格，一个都没命中。
  改成整行去空白归一化后精确匹配。
- **不再只报文件开头**：从「按文件顺序取前 4 条」改成**按位置均匀铺开（首尾必含）**，
  122 块的文件现在能点到章末。
- **清单上限 4 → 12 条**（可读性上限，字数上界 228 字 ≈ context 的 2.9%）；
  页首是正文长句、没有标题的页（占 34.6%）改为用「第 N 页」诚实命名，且排在标题条目之后。

实测：点名条目 84 → 244、被点名的行政页 1 → 0。

### 5. 指代式定位：问句点了文件标题也能定位（检索）

「k近邻那份材料讲了什么」以前不定位到具体文件。现在除了章号，还认「指代 + 材料」标记 +
文件标题前缀（≥3 字），且要求**证据串在语料里唯一**、最长命中优先 —— 误定位 0（22 条标注）。

### 6. 发版链路：Release 正文不再是空的（构建）

`--generate-notes` 在「直推 main、没有 PR」的仓库里只产出一行 Full Changelog（v1.1.0 /
v1.2.0 / v1.2.1 三次都验证过）。现在工作流先跑 `scripts/check_release_notes.py`
（缺 `docs/release-notes-<版本>.md` 或 <400 字符就让工作流红），再用 `--notes-file` 建 Release。

## 验证

- `pytest`：**835 passed**（v1.2.1 时 829；本轮两组变异检查 5/5 + 4/4 全红）
- README 的机械部分（测试条数 / 结构树 / 格式表）由 `scripts/sync_readme.py` 生成，CI `--check`
- 安全判据含真 uvicorn + curl 冒烟（无 token 5 项、有 token 4 项、公开监听拒绝启动 1 项）

## 升级注意

1. **对外部署**：确认客户端能处理 HTTP Basic（浏览器会弹一次框，前端不用配）。
2. 老会话升级后第一次访问会被绑定归属令牌（正常）；想彻底关掉这个窗口见 `SESSION_BIND_LEGACY`。
3. 覆盖说明的清单变长了（最多 12 条）——context 多 ≤228 字，实测中位 122 字。

## 已知限制

- 缺口清单**仍不判轻重**（语料里没有可验证的「哪页更重要」信号）；
- `md` / `docx` 没有「页」的概念，那里的「页标题」其实是块首行；
- 多用户账号 / 权限分离 / 审计**仍未做**：`AUTH_TOKEN` 是共享钥匙，知道口令就能读写全部对话；
- 限流仍是进程内内存（多实例不共享）。
