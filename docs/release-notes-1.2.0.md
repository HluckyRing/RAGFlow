# v1.2.0 — 拆问、覆盖说明、范围词、安全闸门

> 自 `v1.1.0`（2026-10-05）以来 **79 个提交**（43 个 feat/fix/perf/refactor，33 个 docs），
> 测试 **182 → 768 passed**。本版是检索层的一次整体升级，同时改了 4 处默认值——升级前请先看
> 「破坏性变更」和「默认值变化」两节。

## 亮点

### 1. 查询分解（拆问）默认开启

复合提问先过一道廉价闸门 `looks_compound`，通过后让模型拆成子问，**每条子问单独检索**
（不调 HyDE，否则延迟翻倍），再轮流分名额合并进同一份 context；多轮对话里每条子问还会各走一次
`resolve_query` 消除指代。

- 开关：`DECOMPOSE_ENABLED=1`（默认开）、`DECOMPOSE_MAX_PARTS=6`
- 实测（5 块上下文预算、37 条可用子问）：整句 45.9% → **分路 81.1%**；模型拆问 qmark/comma/runon
  三臂 78.4% / 81.1% / 83.8%，平均拆 2.69 问，条数与 gold 逐条相同，退回整句 0 条
- 多轮省略式写法：「现状数整句 53.3% → 拆问不消解 46.7% → 拆问 + 逐条消解 **73.3%**」
  （省略式那一半 25.0% → 75.0%）
- 调用率 22.9%，单问误判 1/59，live 延迟中位 0.66s / p90 1.07s，解析失败 0/19

### 2. 覆盖说明：只摘了一部分，就说出来

文件内跨节取样（`COVERAGE_INTRA_FILE=1`，即点名「第一章」时把那一章按页铺开、块数按字符预算
反推）上线，并配一条**覆盖说明**：context 最前面插一句【覆盖说明】告诉模型「别假装看全了」，
SSE 额外推 `coverage` 事件（与 `sources` 同在首 token 之前），前端渲染「本次只摘录了《X》的
43/110 段」小标签。**拒答时不推也不落盘**（与「拒答不挂 sources」同一条纪律）。

- 实测：PPT 29/30 段（97%）、机器学习 3 份 PDF 14/15（93%），零回归；代价是 context 中位
  7 560 / 8 000 字符
- 触发条件很窄：枚举 / 汇总类措辞 **且** 点名了明确章号

### 3. 范围词当文件过滤器（`SCOPE_FILTER=1`）

问句点名章号且唯一匹配到一份文件时，检索加 `where={"file_name": ...}`，并把「结合第2章课件，」
这类范围短语从**检索探针**里删掉；空命中自动退回全库，认不准就不动手。

- 实测（12 条带范围词提问 / 257 块 / 真 HyDE）：事实核 **11/14 → 13/14**、整条答到
  **10/12 → 11/12**、命中目标文件 **11/12 → 12/12**，逐条无回归，负样本误召回不变，
  检索 50 → 61 ms

### 4. 检索与拒答链路的其余改进

- **双路融合**（`FUSION_ENABLED=1` + `FUSION_GATE=intersect`）：原问题 + HyDE 各一路探针，
  RRF 合并名次；配 `FUSION_CANDIDATES` 候选池开关（默认 0）
- **关键词兜底切片缓存**：兜底块不再每次重算
- **可答性判断**（`ANSWERABILITY_CHECK`，默认 0）：检索出 context 后再问一次「材料能否回答」，
  必须逼模型摘原文依据——域内无答案负样本 8/8 拦下，正样本 0/36 误杀，0.78 s/问，失败 fail-open
- **拒答可见**：结构化标记 + `refused` 事件 + 前端标签；拒答时报「已检索 N 个文件」（只给计数）
- **部分可答**：过度拒答 5/8 → 0/8，答了 + 点明缺口 3/8 → 8/8
- **跨编码器精排**（`RERANK_ENABLED`，默认 0）：线上口径把无关提问误召回压回 0/5

### 5. 安全与工程

- **公开监听 fail-closed**：绑定非回环地址且没设 `AUTH_TOKEN` → **拒绝启动**
- **按 IP 限流**：`/api/chat` 默认 20 次 / 60 s 滑动窗口（`CHAT_RATE_LIMIT` / `CHAT_RATE_WINDOW`）
- **闸门措辞表外置** `src/gates/`（`GATE_PACK` 可插拔），带 hit/miss 日志与「0 触发」告警；
  语言无关的结构页判据（4-gram 跨 ≥3 文件）
- **README 机械部分自动化**：`scripts/sync_readme.py` 生成测试条数 / 结构树 / 格式表，CI 跑
  `--check`，另有一组 pytest 守卫
- 新增两块「便宜守卫」测试：README 与 `.env.example` 里的每个 `NAME=…` 必须在 `src/` 真有实现

## 破坏性变更

| 变化 | 影响 | 处理 |
|---|---|---|
| 公开监听无 `AUTH_TOKEN` 拒绝启动 | 原本直接 `HOST=0.0.0.0` 裸跑的部署，升级后**起不来** | 设 `AUTH_TOKEN`，或改绑 `127.0.0.1` |
| `CHUNK_SIZE` 默认 600 → 480 | 旧索引与新默认值不一致 | 用默认值重建索引后行为才与实测一致 |

## 默认值变化

| 变量 | v1.1.0 | v1.2.0 | 说明 |
|---|---|---|---|
| `DECOMPOSE_ENABLED` | 无 | **1** | 拆问默认开 |
| `COVERAGE_INTRA_FILE` | 无 | **1** | 文件内跨节取样默认开 |
| `COVERAGE_CROSS_FILE` | 无 | 0 | 线上预算下实测 no-op，保持关 |
| `SCOPE_FILTER` | 无 | **1** | 范围词当文件过滤器 |
| `FUSION_ENABLED` / `FUSION_GATE` | 无 | 1 / `intersect` | 双路融合 |
| `RERANK_ENABLED` | 无 | 0 | 可选精排 |
| `ANSWERABILITY_CHECK` | 无 | 0 | 可选可答性判断 |
| `CHAT_RATE_LIMIT` / `CHAT_RATE_WINDOW` | 无 | 20 / 60 | 按 IP 限流 |
| `CHUNK_SIZE` | 600 | 480 | 适配 embedding 窗口 |

## 已知限制（别照着宣传词想象）

1. **覆盖说明只有总账**：能说「N/M 段」，说不出少的是哪几节（要先解析章内小节标题）。
2. **没有真实身份体系**：只有单一共享 `AUTH_TOKEN`，没有账号、会话归属校验、CSRF；限流是
   进程内内存，多实例不共享。
3. **测量范围很窄**：单一小语料（最大 13 个文件 / 1 061 块）+ 手写提问；`state/` 里只有 12 条
   真实提问、0 条复合问——**拆问在真实流量上从未被触发过**，跨文件取样在线上预算下是 no-op。
4. **部分提问会变慢**：枚举整章那种提问，生成侧实测 17.8 s（回答从「拒答」变成 2–3k 字整章框架），
   复合问首 token 中位 3.6 s；context 上限 8 000 字符。
5. 生成侧「答全率 35% → 90%」是手写真实写法样本的口径，不是真实流量口径。
