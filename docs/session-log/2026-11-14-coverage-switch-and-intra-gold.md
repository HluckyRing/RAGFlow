## 一、为什么要把开关拆开

第十三~十六轮把两套**完全不同**的行为塞进了一个 `COVERAGE_SAMPLING`：

| 行为 | 实测（线上预算） |
| --- | --- |
| 跨文件取样（枚举 / 汇总型提问保证每份文件都有代表块） | **no-op**：实体覆盖 24/38 → 24/38；导航页降权还掉到 20/38（那是 gold 坏了，不是特性坏） |
| 同文件跨节取样（问句点名章号时把那一份文件按节铺开） | **唯一有正面结果的一条**：2/5 拒答 → 5/5 不拒答、+16 ms |

一个开关管两件事，唯一的后果是**没法只开有效的那条**：想开文件内跨节，就必须同时把已经证明是
no-op 的跨文件取样一起打开，于是任何 A/B 都掺了一个已知无效的变量。

现在的语义：

| 开关 | 管什么 | 生效前提 | 默认 |
| --- | --- | --- | --- |
| `COVERAGE_CROSS_FILE` | 按文件轮流取样 + 补位缺失文件 | 枚举 / 汇总措辞 + **≥2 份文件** | 0 |
| `COVERAGE_INTRA_FILE` | 点名章号时把那一份文件按节铺开 | 枚举 / 汇总措辞 + **认得出章号**（**一份文件也能用**） | 0 |
| `COVERAGE_SAMPLING`（老） | 兼容别名：= 两个都开，并打一次 WARNING | —— | （不设） |

两条**语义取舍**（都有测试钉住，也写进了 `AGENTS.md`）：

1. **只开跨文件**时，点名章号的提问**退回第十三~十五轮那条路**（按文件取样 + 每份缺失文件补位
   3 个候选）—— 这样 `COVERAGE_CROSS_FILE=1` 精确复现拆开前的行为，做 A/B 只差一个变量；
2. **只开文件内**时，没点名章号的枚举型提问**原样返回** —— 那是另一套行为，不许顺手带上，
   否则「只开有效的那条」就变成了「开着一条、悄悄做另一条」。

顺带修掉一个边界：拆分前 `len(files) < 2` 在函数最前面就把**所有**取样挡掉了（包括文件内跨节），
现在只有跨文件那条要求 ≥2 份文件，**单文件语料也能「整理第一章」**。

`coverage_switches(env)` 把解析逻辑单独抽成函数：`import` 时读一次环境变量在测试里没法干净重放
（`importlib.reload` 会连 OpenAI client 一起重造），而老开关的兼容语义恰恰必须被钉住。

## 二、gold 扩到 6 条：怎么标的

第十六轮那条「整理第一章」只算 1 条有效样本（涨 1 条就是 2.6pp），不够谈默认值。这一轮在同一份
13 文件语料（12 章 PPT + 全书习题答案）上补到 **6 条「帮我整理第N章的内容」/ 30 个事实核**：

- 每章 **5 个节级术语**，一个事实核一个术语（沿用第十一轮/第十四轮口径，**避开章节标题**——
  每份 PPT 的「知识导图」页都列全部章名，拿章名当核会让「只读到一页导图」判成全中）；
- **三条离线校验**（`.agents/make_intra_gold.py`，不花 API）：① 术语必须**逐字**出现在**目标那一章**；
  ② 打印术语在该章的**页码跨度**，确认它铺开在首/中/尾而不是挤在开头；③ 跨多文件出现的泛词标 ⚠；
- 一个事实核允许带**同义写法**，判定时任一词面命中即算答到（修「量尺比模型脆」的老毛病）。

| 章 | 事实核（括号里是页码跨度 = 铺开的证据） |
| --- | --- |
| 1 | 目标和作用(7–55) · 发展过程(7–55) · 基本特征(7–55) · 运行环境(7–55) · 主要功能(2–55) |
| 2 | 前趋图(3–47) · 进程控制块(9–19) · 原语(24–34) · 消息传递(32–34) · 用户级线程(48–54) |
| 4 | 临界资源(4–67) · 信号量(12–72) · 生产者-消费者(5–59) · 读者-写者(37–64) · 资源分配图(100–110) |
| 5 | 逻辑地址(9–13) · 对换(3–76) · 首次适应算法(31–32) · 页表(49–61) · 段表(66–68) |
| 6 | 最近最久未使用/**LRU**(19–25) · 缺页中断(9–42) · 局部性原理(7–35) · 抖动(3–41) · 内存映射文件(3–41) |

## 四、抓到的真 bug：目标文件一块都没命中时返回空 context

第 2 章第一次跑 ON 臂时 `returned=0`、`answer` 为空。顺着查：

1. 整句检索（HyDE + `intersect` 距离闸门）**一块都没过**，退回**关键词兜底**；
2. 兜底回来的块**没有 metadatas**（`meta=None`）→ 「属于目标文件」的过滤结果 `inside` 为空；
3. `blocks_that_fit([], ...)` 返回 **0**，而判断写的是 `len(inside) < blocks` —— **`0 < 0` 不成立**，
   文件内补位那一支永远不进 → 返回空列表 → 模型拿到空 context → 空回答。

修法：改成 `if not inside or len(inside) < blocks`（`src/llm.py`），加回归测试
`test_intra_file_sampling_backfills_when_the_target_file_has_no_hits`，变异检查第 C 项确认：
改回去测试就红。

**这个 bug 只有「HyDE 写偏 + 目标文件没命中」时才会出现** —— 单条样本的口径永远碰不到它。
扩 gold 到 6 条碰巧撞上了，这是本轮最有价值的副产品：**样本一多，踩到的就不是同一种失败了**。

## 五、默认值：仍保持 0，但判据写死

1. 质量门这次是真过了，而且不再是一条样本（4/30 → 27/30、拒答 4/6 → 0/6）；
2. 但只有**一份语料**，且是 PPT 式「节 = 页」；md / pdf 的 `section` 形态不同，第十六轮就写着这条；
3. 延迟是**产品决策**：+10 s 生成 / +3.6 s 首字，要不要为「整理整章」付这笔钱，不是评测能拍板的；
4. 章号定位只认「第N章」，接不住「这份材料」「上面那个实验」。

**判据**：换 md/pdf 语料后同口径仍 ≥90% 且无回归，就把 `COVERAGE_INTRA_FILE` 默认改成 1。
开关已经拆好了，所以这条结论不再等任何代码改动 —— 差的只是第二份语料 + 一条产品侧的延迟预算。

## 六、坑

1. **一个开关管两套行为，等于两套都评估不了**。想只开有效的那条都做不到时，先拆开关再谈数字。
2. **兼容别名必须出声**：`COVERAGE_SAMPLING=1` 悄悄代表两件事，评测脚本还在用它 —— 留着但打
   WARNING，否则下一个人会以为它只管一件事。
3. **样本一多就会踩到新的失败模式**：单条样本时「目标文件一块都没命中」这条路根本没被测过，
   而它一踩就是**空 context + 空回答**（用户看到的是空白）。空结果必须当错误路径对待。
4. **量尺假阴性又来了两次**（第 5、6 章）：模型写 LRU、写「装入/逻辑地址」而不写「重定位」。
   老规矩 —— **先读原文，再怀疑特性**；改完量尺两臂一起离线重算。
5. **延迟要按回答长度解释**：ON 臂慢 10 s，但回答从「拒答一句话」变成「2–4k 字整章框架」，
   把这两个数并列时不加一句解释就是误导。
6. **默认值不是评测能单独拍的**：质量门只说明「开比关好」，要不要付延迟是产品侧的事。
