# 2026-11-19 范围词 → 文件过滤器（`SCOPE_FILTER` 默认开）

> 起因不是需求，是一次**用户提问**：同一个人、同一份知识库、同一条问题，只差「结合第2章课件」
> 这五个字，一个拒答、一个答对。本轮把这个差异追到根、改掉、量出来。

## 1. 起点：两条真实的回答

`state/36e93a78c0dcc1e11b0afc1dd13f21d9.json` 里留着原始记录（3 份机器学习 PDF / 257 块）：

| 问法 | 结果 | 引用 |
|---|---|---|
| 「**结合第2章课件**，在同一训练集上不断提高多项式回归的阶数，通常可以观察到什么」 | `refused=true`、`searched_files=1` | 只有《第1章 绪论》p46「回归问题的工作框架」 |
| 「在同一训练集上不断提高多项式回归的阶数，通常可以观察到」 | 正常作答 | ch1 p72/p73 + **ch2 p91（欠拟合/过拟合页）** |

用户的直觉是对的：**人**会先定位到第 2 章那份 PPT，再在里面找；**系统**把「第2章课件」当成了
检索词。这不是语料问题 —— 第 2 章 p91 明明在库里。

## 2. 复现与定位（只读，没动线上数据）

用同一个 chroma 集合 + 同一份 HyDE 口径重跑，两条回答**逐块**复现（1 块 vs 3 块）。结论是两层叠加：

1. **元信息词被当检索词。** 原问句探针的前 10 名里，第2章的封面页(p1)、内容提要页(p2/p38)、
   本章数学知识(p3)、多项式回归定义/例题(p28/29/34/35/106) 占了大部分名额 —— 它们与
   「第2章」「课件」「多项式回归」字面最像。**答案页 p91 从第 8 名掉到第 16 名**。
   距离始终 0.39–0.43 ≪ `MAX_DISTANCE=0.55`：**不是阈值筛掉的**。
2. **`intersect` 闸门把交集塌成 1 块。** HyDE 探针里 p91 是**第 1 名**（dist 0.233），
   但闸门要「两路都召回」，两路 top-10 只交到 ch1 p46 那块「什么都能沾一点」的通用页。

消融（只换前缀片段）证明是**「第2章」三个字**在拉偏原问句探针：只留「第2章，」→ p91 第 18 名；
只留「结合课件，」→ p91 第 7 名、唯一命中反而是它；不带前缀 → 第 8 名、命中 3–4 块。
同一句的候选池敏感性：`top_k` 10 → 交集 1 块、15 → 1、20 → 5、30 → 11。

## 3. 改动

- **`src/scope.py`（新，纯函数）**
  - `strip_scope(question)`：删掉「（请/帮我/结合/根据/参考/按照/依据/基于）+ 第N章 +（的）+
    课件/讲义/PPT/幻灯片/材料/教材/教案 + 标点」，**删完太短（< 4 字）就不删**；
  - `scope_target(question, file_names)`：用**已有的** `coverage.chapter_numbers` +
    `coverage.pick_target_file` 把章号映射到**唯一的一份文件**；没有章号 / 匹配到多份 → `None`。
- **`src/retrieval.py`**：定位成功 → `where={"file_name": …}` + 探针换成改写后的问句
  （HyDE 也基于改写后的问句生成）；**范围过滤空命中自动退回全库**并记 WARNING；
  新增 `FUSION_CANDIDATES` 候选池放大（默认 0 = 现状）。
- **开关**：`SCOPE_FILTER`（默认 **1**）、`FUSION_CANDIDATES`（默认 **0**），`.env.example` 已同步。

## 4. 实测

提问集 `tests/fixtures/scope_queries.json`：12 条「结合第N章课件，…」/ 14 个事实核，
**离线校验逐字**落在目标文件里（`scripts/eval_scope_filter.py --verify-only`，不对就退出码 2）。
负样本：`eval_queries.json` 的 15 条 `far`。语料 257 块、真 HyDE、`top_k=10`。

| 臂 | `SCOPE_FILTER`/`FUSION_CANDIDATES` | 事实核 | 整条答到 | 目标文件 | 块数中位 | 字符中位 | 检索中位 | 负样本误召回 |
|---|---|---|---|---|---|---|---|---|
| base | 0 / 0 | 11/14 | 10/12 | 11/12 | 5 | 1 053 | 50 ms | 10/15（向量 3/15） |
| pool | 0 / 20 | **14/14** | **12/12** | 12/12 | 10 | 1 636 | 52 ms | 10/15（3/15） |
| scope | 1 / 0 | 13/14 | 11/12 | 12/12 | 6 | 1 099 | 61 ms | 10/15（3/15） |
| both | 1 / 20 | **14/14** | **12/12** | 12/12 | 10 | 1 512 | 65 ms | 10/15（3/15） |

- **scope 臂逐条无一变差**：真实拒答那条 s01 从 0/2 → 2/2；s12（「k 近邻为什么不需要建立模型」）
  仍 0/1，只有 `pool`/`both` 用更多 context 把它捞回来。
- **scope 臂的所有命中都在问句点名的那份文件里**（来源只剩 1 份）；`pool` 会把 3 份都拉进来。
- 负样本误召回三条臂**完全不变**（10/15；走向量那条 3/15）—— 这次没有用精度换召回。

默认值：`SCOPE_FILTER=1`（四道门全过：质量 / 负样本 / 代价 +11 ms / 回退逐位不变）；
`FUSION_CANDIDATES=0`（收益与 scope 重叠，代价是 context 翻倍 → 留开关）。

## 5. 验证

- `pytest -q` → **768 passed**（起点 750：15 条 `tests/test_scope.py` + 2 条
  `tests/test_repo_hygiene.py` 的文档漂移守卫 + 1 条 README 同步守卫）。
- 变异检查 **4 项全红**：无视 `SCOPE_FILTER` 开关 / 删掉「退回全库」/ 删掉块预算截断 /
  只删范围词但不过滤。
- 冒烟（13 份 PPT / 1 061 块，固定 HyDE 排除随机性）：`帮我整理第一章的内容`、
  `第2章讲了什么` 两臂**完全相同**（47 块 / 7 441 字符）—— 整章枚举那条路没被碰到；
  `第2章讲了什么`（没有「课件」二字、仍点名章号）从「全部落在习题答案 PDF」变成
  「落在第2章 PPT」。

## 6. 坑

1. **`git checkout -- <file>` 把本轮改动全抹了**：做变异检查时用 `git checkout` 还原一个
   *已修改未提交* 的文件 = 直接回到 HEAD。正确做法是先 `Copy-Item` 到 `.agents/` 里再改，
   或用 `git stash`/补丁。这次是重新敲了一遍 `retrieval.py` 的两处改动。
2. **延时被 HyDE 污染**：第一版脚本每个臂只跑一遍，先跑的臂替后面所有臂付了 API 延迟，
   量出来 `base 1.508 s` vs `pool 0.050 s` 的鬼数字。改成「第一遍只灌缓存、第二遍才计时」。
3. **默认语料选错**：脚本原先按「文件最多」选语料，选中了 13 份 PPT 那份，事实核校验全线报错。
   改成**按事实核点名的文件名反查**语料（选错语料在第一步就露馅）。
4. **负样本「误召回」要分路**：`bool(hits)` 会把关键词兜底也算进来（本项目的老教训）。
   本轮补了 `path` 统计（向量 3/15），三条臂一致 —— 否则看不出「是不是池子放大把噪声放进来了」。
5. **文档里的硬数字没人管**：顺手查了 `README.md`，发现「750 passed」「1998 行基线」「这个服务
   没有鉴权」三处全部过期，且基线行数在同一个文件里写了 **3 个互相矛盾的数**。已按实际改齐
   （768 passed / 2691 行 / 安全段重写 / 亮点 +3 / 实测数据 +3 行 / 结构 +6 个文件），并补了
   **两条守卫** `tests/test_repo_hygiene.py::test_env_example_only_documents_real_variables`
   与 `::test_readme_only_mentions_real_variables`（README / `.env.example` 提到的变量必须在
   `src/` 里真实存在；两项变异检查各变红一次）。
6. **「数字靠人肉同步」这件事本身不可靠**：上面那轮改完，紧接着加了 2 条测试 → 767 立刻过期、再补 1 条又变成 768，
   又手工改了 7 个文件才对齐。所以补了 `scripts/sync_readme.py`：
   - README 里用 HTML 注释标记（`<!-- AUTO:test-count -->768<!-- /AUTO:test-count -->`、
     `<!-- AUTO:structure -->…`、`<!-- AUTO:formats -->…`），脚本只重写**标记之间**的内容；
   - `--write` 重写、`--check` 只比对（CI 里加了一步 `python scripts/sync_readme.py --check`）；
   - 结构树的说明来自脚本里的 `DESCRIPTIONS`（**不是** docstring —— `config/llm/retrieval/server`
     等一半模块没有 docstring），新增文件却没写说明时脚本**报错退出**；
   - 支持格式表直接与 `loaders.SUPPORTED_EXTENSIONS` 对齐，多一个少一个都报错。
   变异检查两项：手动往结构树塞一行 → `--check` 退出码 1 且 pytest 守卫变红；新增一个没有说明
   的 `src/_probe_module.py` → 脚本点名要一句说明。**留给人的仍然是人话**：为什么这么做、
   哪条路被证伪了、实测数字（11/14 → 13/14）—— 这些算不出来，脚本一个字都不碰。

7. **提交拆分要把「谁依赖谁」拆对**：用户要三个提交（① 功能 ② README 对齐 ③ 文档工具），
   第一版拆成「② README 对齐 + sync 脚本 + CI + 守卫 / ③ 只放归档文档」，结果逐提交验证时 ② 红：
   `test_readme_mechanical_blocks_are_in_sync` 失败 —— 因为 README 里的 `AUTO:docs-lines`
   （基线文档行数）落在 ③、`AUTO:test-count` 依赖的守卫测试又落在 ②，于是 ② 单独跑时
   「README 说 2691/768，实际 2600/765」。**正确的拆法是按依赖闭包拆**：
   docs 一个提交（不碰测试）→ 工具链一个提交（脚本 + CI + 守卫同进退）。
   纪律：**push 之前逐个 `git checkout <commit>` 跑一遍 `pytest -q`**（本轮三次验证：
   765 / 765 / 768 passed），否则推上去的历史里会夹着一个红的提交，`git bisect` 也会被骗。

## 7. 量不到

- **单一语料 + 12 条手写提问**：真实用户带范围词的流量为 0；13 文件 PPT 那份只做了冒烟、没有 gold。
- **`FUSION_CANDIDATES` 在「没有章号」的普通提问上没测**，收益/代价未知。
- 范围短语只认「第N章（的）+ 课件/讲义/PPT/材料…」这几种写法；`那份课件`、`第二章那份材料`、
  `上面那个实验` 这类**指代式范围**一律不触发（仍是「章号之外的指代定位」那条老待办）。
- 文件名里不带「第N章」时不会过滤（`操作系统引论.pptx` 这种就漏了）。

## 8. 复现命令

