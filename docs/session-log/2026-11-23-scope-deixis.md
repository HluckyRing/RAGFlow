# 2026-11-23 指代式定位：标题词唯一匹配（待办 ④）

> 待办原文：「『这份材料』『上面那个实验』现在一律不定位」。做完的结论是：

> 数字见 `docs/retrieval-baseline-2026-10-06.md` 的「指代式定位」一节。

## 一、先量再改（这轮最省时间的决定）

`.agents/probe_scope_deixis.py` 把待办里那几种说法全跑了一遍，量出三件事：

1. 「**第二章那份材料**里的正则化」**本来就已能定位** —— 有章号，走的是 2026-11-19 那条路；
   待办里把它和「这份材料」并列，其实两者性质不同。
2. 真正失效的是「**点了文件标题却没有章号**」那一类（操作系统引论那个课件 / 虚拟存储器那份材料 /
   决策树那份 PPT / k近邻那份材料）—— 4 条全返回 `None`。
3. 「这份材料」「上面那个实验」不只是「没实现」，而是**没有依据**：前者需要对话级信息，
   后者指的压根不是文件。硬猜会把答案锁死在错的文件里。

先量清楚，省掉了「给所有指代加一套猜测规则」这条**注定要回滚**的路。

## 二、规则与判据

四条同时满足才动手：指代+材料标记、标题前缀 ≥3 字、**最长命中优先 + 证据串在语料里唯一**、
定位后清理探针里的包装词。判据与结果：误定位 **0**（22 条标注样本）、新能力 5/5 + 3/3、
对照零变化（12 条 `scope_queries.json` 经验值 0 差异）、变异检查 **5/5 红**、`pytest` 786 → **801**。

## 三、实测抓到的误定位（这轮唯一一次返工）

第一版只做「最长命中」：问「存储器那份材料讲了什么」，最长命中是 `存储器管理` 的前缀「存储器」→
锁定第5章。但「存储器」同时出现在 `虚拟存储器`（第6章）与 `磁盘存储器管理`（第9章）的标题里，
用户指哪份说不清。加上「证据串必须在语料里唯一」这一级后才返回 `None`。

**教训（第三次同型）**：`None` 要留给出路最少的那一侧 —— 定位错了比不定位更糟，
所以「唯一」要按**语料里的实际共享情况**判，不是按「我们自己的打分最高」。

## 四、为什么这轮比前几轮好量

定位是**纯函数、零 API 调用**，判据是标注集上的确定性指标（命中/误定位），不涉及模型随机性，
所以不需要「两遍两臂」。前几轮那些「量尺比模型脆」的教训在这里不适用 —— 但代价也明摆着：
**只回答了「认不认得出」，没回答「认出之后答得更好没有」**。
