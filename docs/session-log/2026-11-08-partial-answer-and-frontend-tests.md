## ① 部分可答的提问（复合问题）

### 为什么这一类最重要

此前 67 条样本要么**全答得上**、要么**完全答不上**，而产品里最常见的形状是
**一个问句里一半有答案、一半没有**（「年假有几天，病假工资怎么算」）。这种样本一条都没有，
所以「整条回答被标成拒答」这种**过度拒答**根本测不出来。

### 样本设计：两条**相反**的纪律

`tests/fixtures/eval_queries.json` 新增 `kind: "partial"` 8 条，字段：

- `answer_terms`：可答部分的关键事实，**必须真的出现在语料里**；
- `absent_terms`：语料里没有的那半个问题的主题词，**必须真的不在语料里**。

两条都用测试钉住（`test_partial_answer_terms_really_appear_in_corpus` /
`test_partial_absent_terms_really_are_absent`）——`answer_terms` 要像 `gold_phrases` 一样有保险丝，
`absent_terms` 要像负样本一样有保险丝，否则两个方向都会让指标变成假的。

### 五桶判定（`scripts/measure_inline_abstention.py::classify_partial`）

| 桶 | 含义 |
| --- | --- |
| `refused_all` | 整条消息被标成拒答，可答部分也没答 —— 最糟 |
| `refused_despite_answer` | 整条被标成拒答，但正文其实答了 —— 用户仍然看到「知识库里没有」，仍算过度拒答 |
| `answered_with_gap` | 正常作答 + 点明缺什么 —— **理想** |
| `answered_silently` | 答了可答部分，但对缺的那半只字不提 —— 有编造/含糊风险 |
| `neither` | 可答部分没答到、也没提缺口 —— 答偏了 |

`refused_despite_answer` 这个桶是第一轮跑完才补的：最初把「标了标记」一律算成 `refused_all`，
而看原文发现 5 条里**每条正文都答对了可答部分**，只是整条消息以 `【无答案】` 开头。

### 第一版结果：5/8 过度拒答

提示词当时只有一句「没有答案就以 `【无答案】` 开头」，于是模型把**整条回答**打上标记，
哪怕正文已经答对了那一半（`p04` 明确写了「一线城市每晚不超过 600 元」）。
前端据此会显示「知识库里没有能回答这个问题的内容」—— **标记语义错了**：它该表示
「整条答不了」，不是「有一半答不了」。

### 提示词改两处，四项指标同时达标

1. 三档口径：**完全没涉及** → 写标记；**只答得了一部分** → 先正常作答并标来源、再说明缺哪部分，
   **不许写标记、不许因此丢掉能答的部分**；**能完整回答** → 正常回答。
2. 划清「材料只在讲**相关话题** ≠ 回答了用户问的那件事」（用户问「能不能折成工资」，
   材料只写「逾期作废」→ 算完全没涉及）。

| 指标 | 改前 | **改后** |
| --- | --- | --- |
| 部分可答 · 过度拒答 | 5/8 | **0/8** |
| 部分可答 · 答了可答部分 + 点明缺口 | 3/8 | **8/8** |
| 域内负样本正确拒答 | 8/8 | **8/8** |
| 远域负样本正确拒答 | 2/2 | **2/2** |
| 正样本被误拒 | 0/36 | **0/36** |
| 生成耗时中位 | 1.54 s | 1.55 s |

中间版本值得记一笔：只加「措辞不同也算」那类放宽，会把域内负样本从 8/8 掉到 7/8
（`n23`「调休没休完能不能折成工资」被当成「部分可答」而没写标记，虽然正文说了「文件中没有相应规定」）。
补上第 2 条「相关话题 ≠ 回答了用户问的那件事」之后才两边都对。

### 顺带修掉的标注错误

## ② 拒答时报「已检索 N 个文件」

上一篇把拒答的 `sources` 去掉了（避免让人以为那些文件是答案出处），但「查过什么」全丢也不对：
用户需要知道「我的文件到底被看了没有」。折中方案 —— **只给计数、不给文件名**：

- `chat()` 数一下装配 context 时真正用到的**不同文件**（按**文件名**去重，不按页）；
- `refused` 事件带 `searched_files`，落盘也带上（刷新后标签还在）；
- 前端标签：`⚠️ 知识库里没有能回答这个问题的内容（已检索 N 个文件）`。

真实 uvicorn 冒烟（上传 2 个文件，问「恢复演练要请哪些人参加」）：
`refused` 事件 `searched_files=1`（只有备份规范的块进了 context）、无 `sources` 事件、
落盘 `(refused, searched_files, has_sources) = (True, 1, False)`。

**边界**：N 数的是「进了 context 的文件」，整篇被闸门挡掉的文件不计入。想表达
「你上传的 5 个文件都看过」得换成数会话文件总数 —— 那是另一个口径，已记进待办。

## ③ 前端拒答标签的真渲染测试

静态守卫（`tests/test_frontend.py`）只能证明「index.html 里有这行」，证明不了渲染结果。
新增 `tests/test_frontend_render.py`：

1. 从 `index.html` 里**按花括号配对照切出真实函数源码**（`buildRefusedTag` / `showRefusedTag`）；
2. 用 **Node 内置 `vm`** 跑，配一个极小的 DOM 替身（`createElement` + 节点树 + `querySelector`）；
3. 五条断言：无计数时不出现空括号、有计数时是「（已检索 2 个文件）」、**非数字/undefined 不加**、
   `showRefusedTag` 重复调用不叠第二个标签、**拒绝 `innerHTML`**（替身 setter 直接抛错）。

三条纪律：**不引 npm 依赖、不装 headless 浏览器**（前端本来是零依赖原生 JS，测试不该给它加工具链）；
本机没有 `node` 时整组 `pytest.skip`（CI 的 ubuntu runner 自带 node，会真跑）；
切不出完整函数就**大声报错**，绝不返回半截。

反向对照：把 `tag.textContent = text` 临时改成 `tag.innerHTML = text` → 4 条全部变红，还原后全绿。

## 踩过的坑

1. **命令行里套多行 Python 又炸了**（第二次）：`pwsh` 的 `@"..."@` 里放带引号的多行 Python，
   报 `SyntaxError: unterminated string literal`。**长脚本一律用 write 工具落到 `.agents/*.py` 再跑** ——
   这次彻底改用这条路，后面没再踩。
2. **反向对照后重写 `index.html` 差点改掉行尾**：Python 文本模式在 Windows 上会把 `\n` 写回 `\r\n`，
   所以这次侥幸没坏；但 `git status` 仍显示 ` M`（只有 stat 变化，`git diff` 为空）——
   用 `git update-index --refresh` 之后确认没有内容差异。**改 HTML 后要显式查 CRLF 数量**。
3. **冒烟的问题选得太「远」**：第一次冒烟问「异地机房怎么切换」，检索侧直接返回空（走了 400 路径），
   根本没有 `refused` 事件可看。冒烟要挑**域内无答案**的问题（「恢复演练要请哪些人参加」）。
4. **分类桶不够细**：`refused_all` 一开始把「标了标记但正文答了可答部分」也算进去，
   于是 5/8 被误读成「一个字都没答」。补 `refused_despite_answer` 后才看清真相。
5. **标注错会让指标变成假的**：`p08` 的 `answer_terms` 写错（升温 vs 降温），
   差点把模型的正确行为判成失败。
6. **`git status` 的 ` M` 可能是 stat 缓存**：`git diff` 为空 + `porcelain=v2` 显示同一个 blob 哈希，
   就说明文件内容没变。
