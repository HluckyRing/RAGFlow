# v1.2.1 — 覆盖说明点名「缺的是哪几页」

> 一个功能提交（配合 v1.2.0 之后的第一版）：**没有破坏性变更、不需要改任何配置**，
> 想回退只需设 `COVERAGE_INTRA_FILE=0`（整条覆盖取样关掉）或退回 v1.2.0。

## 亮点

### 覆盖说明会说「缺的是什么」了

v1.2.0 的覆盖说明只有总账：「本次只从《第5章 存储器管理.pptx》里摘录了 48/86 段」——
用户看完只知道少了，不知道少什么；模型照着这句话也只能含糊说「只覆盖了一部分」。

现在多一句**缺口清单**，点名哪些页标题一次都没读到：

> 【覆盖说明】本次只从《第8章 文件管理.pptx》里摘录了 50/67 段（按页均匀取样），
> 这些页标题一次都没读到：`8.1 文件和文件系统`、`文件类型(1)`、`8.1.4 文件操作`、
> `8.2.2 顺序文件1` 等 16 个页标题。回答时请如实说明「本次只覆盖了这份文件的一部分」，
> 不要假装看过全部内容。

- **页标题怎么来**：块前 3 行里第一个像标题的行 —— 去掉 `67 / ` 这类页码前缀、跳过
  `Date`/`Signature`/版权行、结构页（`内容导航：`、`第N章知识导图`）就地判死、
  正文行（> 24 字）直接放弃、截到 18 字。
- **缺失怎么算**：没进 context 的块的标题 − 进了 context 的块的标题。同一标题连排多页时
  （「岭回归」连排 3 页），读到 1 页就算这个标题摸到了 —— 不夸大缺口。
- **展示 4 条** + 「等 N 个页标题」；解析不出任何标题的语料上**逐字退回** v1.2.0 的话术，
  一个字都不编。
- 三处同一本账：context 里的【覆盖说明】、SSE 的 `coverage` 事件（新增
  `missing_titles` / `missing_count`，纯新增字段）、前端标签与消息落盘。

### 为什么不是「按小节编号」

做过原型，实测是坏的：PPT 的「内容导航：」页**一次性列全章小节、不带「哪一节从哪页开始」**，
只能靠「页首标题 ≈ 小节标题」去猜 —— `1.6 操作系统的结构设计` 的正文页首行是
「操作系统结构设计」（少个「的」）就锚不上，导致整节被剔除、上一节的区间顺势吞掉它；
第4章还会算出 `p12-0` 这种负区间；机器学习 PDF 没有编号大纲，正文算式反被当成小节标题。
**猜错的「缺失小节」比不说更糟**，所以退到只报能验证的页标题。

## 验收（四条判据写死后再动手）

| # | 判据 | 结果 |
|---|---|---|
| 1 | 精确率 100%：点名的标题在已读块里一次都没出现过 | 6 份真实文件全部通过；变异检查能变红 |
| 2 | 不编名字：解析不出标题时逐字退回 v1.2.0 话术 | 单测逐字比对 |
| 3 | 字数开销 ≤ 150 字符 | 实测最大 **+64**；6 条整章 gold 的 context 中位 7 667 → 7 706 |
| 4 | 无回归：6 条「整理第N章」gold 事实核 ≥ 27/30 | **29/30、28/30**（两遍）vs v1.2.0 话术 28/30、29/30（两遍）；整章答全 4–5/6；拒答 0/6 |

**它是透明度改进，不是质量杠杆**：两遍两臂事实核 28.5/30 vs 28.5/30 持平，回答本身没有变好；
变好的是用户和模型第一次知道「哪几页一次都没读到」。

## 已知限制

1. 缺口**不排序、不分轻重**：按原文件顺序取前 4 条，说不了「缺的那页是不是关键页」。
2. 页标题靠「第一行」的启发式：PDF 里页首是长句的页会被判「没有标题」，**永远不被点名**
   （宁缺不编的代价）。
3. 「展示 4 条」是拍的上限，没做用户研究。
4. 跨文件那条（`COVERAGE_CROSS_FILE`）仍是 no-op，没做节级账；测量仍在单一语料上。

## 升级

- 不需要改配置；`missing_titles` / `missing_count` 是 SSE 事件的**新增字段**，老前端忽略即可。
- 想彻底退掉这套行为：`COVERAGE_INTRA_FILE=0`，或直接留在 v1.2.0。
